# Демо-сценарии и seed-данные

Компания определяется по пользователю: все пользователи — клиенты банка (`API_SPEC.md`, раздел «Пользователи — действующие клиенты банка»).
Поэтому у каждой ветки «Схемы решения» свой логин. Пароль у всех — `demo123`.

Это общий контракт двух разработчиков:
- **A** заводит пользователей (`internal/identity/migrations`);
- **B** заводит компании (`internal/company/migrations`) и данные моков (`cmd/mocks`).

Меняете строку — меняйте её в этом файле в том же коммите, что и seed.

## Что должно быть в моках (B)

- `core-banking/clients/{inn}` — для каждой компании из таблицы. В `persons` есть пользователь с его `personInn` и ролью: `HEAD` для руководителя и ИП, `REPRESENTATIVE` + `mchdNumber` для `petrova` и `volkov`. Для ООО добавлены учредители.
- `mchd/{number}` — для `petrova` действующая доверенность (`a1b2c3d4-5e6f-4a7b-8c9d-0e1f2a3b4c5d`, до `2027-03-01`, полномочия `CREDIT_APPLICATION`, `BKI_CONSENT`), для `volkov` — истёкшая.
- Остальные источники (ЕГРЮЛ/ЕГРИП, БКИ, ФНС, ГИР БО, суды, обороты) дают ответ, который ведёт ровно в ветку из колонки «Ожидаемый результат».
