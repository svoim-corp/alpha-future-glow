# Контекст проекта и состояние frontend

Срез по коду и проверкам от **21.10.2026**. Это навигация по текущей реализации, а не замена спецификации. При изменении сценария обновляйте соответствующую строку статуса и оставшиеся задачи. «Есть в клиенте» означает наличие React-кода и демообработчиков; это не подтверждение готовности сервера или полного соответствия требованиям.

## Что за продукт

«Умный кредитный кабинет» — веб-кабинет для юридических лиц и ИП, уже обслуживающихся в банке. Он помогает выбрать финансирование, заполнить двухэтапную заявку, получить решение, принять условия, подписать договор и перейти к обслуживанию кредита. Внешние проверки и выдача моделируются; подключения к реальным банковским системам в проекте не предполагаются.

Две роли:

- `CLIENT` — представитель компании: выбирает продукт, задаёт параметры, даёт согласия, отвечает на вопросы банка, принимает оффер и подписывает документы.
- `BANK_OFFICER` — сотрудник банка: работает с очередью, изучает заявку и результаты проверок, запрашивает пояснения, принимает решение или предлагает другие условия.

Основной путь: вход → каталог → черновик → предварительное решение → полная заявка → отправка → проверки/скоринг → решение → оффер → подписание → моделируемая выдача. Запрос информации возвращает клиента к уточнениям; отказ и встречное предложение — отдельные исходы. Точная машина состояний — в разделе 2 [API_SPEC.md](../../API_SPEC.md).

По уточнению от 21.10.2026 реквизиты компании, полномочия и обороты известны банку. Клиенту не нужно вводить их заново или загружать выписки. Текущая реализация ещё содержит старые сценарии. **Ввод ИНН временно сохраняется по решению пользователя от 21.10.2026; исправление отложено до отдельной задачи.** Это ограничение текущей работы, а не новое требование продукта.

## Что есть и что осталось

Маршруты зарегистрированы в [router.tsx](../src/app/routes/router.tsx), пути и построители ссылок — в [routes.ts](../src/shared/config/routes.ts).

| Область / маршрут | Есть в клиенте | Осталось / ограничение |
|---|---|---|
| Вход `/login` | Форма, получение сессии, выход, защита маршрутов по роли | Проверить весь путь с сервером после реализации бизнес-зон |
| Оболочка клиента | Боковая навигация, компания, профиль, темы, уведомления, мобильное меню | Частичный перенос `shell.html`: поиск, язык и настройки из макета не реализованы; демонстрационные элементы не добавлять без задачи |
| Главная `/` | Сводка кредитов, заявки, рекомендации планера | Сейчас заголовок «Мои заявки» и вертикальные блоки. Сетка плиток, приветствие и быстрые действия из `home.html` не перенесены полностью |
| Каталог `/products` | Выбор цели, суммы и срока, подбор, карточки, условия, калькулятор, создание заявки | Реальный Catalog отсутствует; параметры продуктов и расчёты сверять с API, а не со значениями в HTML |
| Заявки `/applications` | Общий список поданных заявок и черновиков, продолжение и удаление черновика | Поиск, фильтры, сортировка и отдельные вкладки из HTML-макета не перенесены. Нужна интеграция с Origination |
| Мастер `/applications/:id/edit` | Два этапа, параметры, автосохранение, предварительное решение, согласия, валидация и отправка | Сохраняется старый ввод ИНН/МЧД, адреса, ФИО/ИНН поручителя и загрузка выписки. Нужна миграция к данным банка и выбору поручителя; ввод ИНН отложен отдельно |
| Заявка `/applications/:id` | Статус, история, пояснения, ответы банку, принятие/отклонение оффера | Сверить типы, команды и вопросы банка с обновлённым контрактом; исключить требования загрузки файлов |
| Подписание `/applications/:id/sign` | Условия договора, согласия, команды подписания и моделируемой выдачи | Сверить комплект документов и печатные формы с текущим разделом 4.7 API; серверные Offer/Servicing пока заготовки |
| Кредиты `/credits`, `/credits/calendar` | Карточки, сводка, платежи и календарь | Серверное обслуживание и сквозная выдача не реализованы; дизайн перенесён частично |
| Планер `/planner` | Календарь, планы и идеи без даты, создание/удаление, рекомендации на главной | Контракт — предложение вне исходного ТЗ; редактирование и полный жизненный цикл состояний/подбора не завершены. В демо нет `PATCH /plans/:id` |
| Документы `/documents` | Библиотека, загрузка, удаление, прикрепление к заявке | Устаревшая функциональность: исключена актуальными требованиями. Убирать отдельной задачей с навигацией, типами, моками и тестами. Документы, сформированные банком к подписанию, сохраняются |
| Поддержка `/support` | FAQ, создание и список обращений | Нужен сервер Support; наличие мока не подтверждает обработку обращений банком |
| Банк `/bank/queue`, `/bank/applications/:id` | Очередь, назначение сотрудника, проверки/скоринг, запрос информации и решение | Серверные Underwriting/Scoring не реализованы. Отдельных HTML-макетов банка в `designs/` нет |

В сервере реализована основа Identity и таблица компаний; у остальных бизнес-зон `Register` пока пустой. `deploy/docker-compose.yml` описывает запуск компонентов, но не подтверждает готовность кредитного конвейера. Сквозной запуск с сервером в рамках этого аудита не проверялся.

## Где менять frontend

Пути ниже — относительно `frontend/`.

- `src/pages/` — страницы маршрутов; `src/app/routes/` — роутер и layouts.
- `src/widgets/client-shell/` — общая оболочка клиента; `src/widgets/bank-header/` — шапка банка.
- `src/widgets/product-catalog/`, `application-wizard/`, `application-tracker/`, `contract-signing/` — основные блоки кредитного пути.
- `src/widgets/my-loans/`, `payment-calendar/`, `planner-board/`, `support-center/` — кредиты, календарь, планер, поддержка.
- `src/features/` — действия: `start-application`, `edit-draft-params`, `request-prelim-decision`, `fill-full-application`, `answer-info-request`, `decide-offer`, `sign-contract`, `make-decision` и другие.
- `src/entities/` — типы, API и представления сущностей. DTO ещё требуют сверки с обновлённым API.
- `src/shared/ui/index.ts` — React UI-kit: кнопки, поля, карточки, бейджи, таблицы, модальные окна, шаги, загрузка файлов и состояния запросов. Наличие `FileUpload` не означает, что загрузка нужна в актуальном клиентском сценарии.
- `src/shared/api/baseApi.ts` — RTK Query, cookie-сессия, типы тегов; `src/app/model/` — стор.
- `src/app/mocks/handlers.ts`, `db.ts`, `fixtures/` — демо API в браузере.
- `test/msw/`, `test/fixtures/`, `test/render.tsx` — моки и инфраструктура тестов; сами тесты лежат рядом с кодом. Демо и тестовые фикстуры — отдельные копии.

Светлая/графитовая темы, рубиновые акценты, нейтральные поверхности и округлые карточки задаются UI-kit. Редактируемые токены — `docs/ui-kit/tokens.json`; CSS витрины — `docs/ui-kit/tokens.css`; подключённая копия в React — `src/app/styles/tokens.css` (через `index.scss`). На дату аудита CSS-копии совпадают. Генератора и автоматической синхронизации нет: изменения согласованно вносить во все три файла.

Композиция страниц переносится в React и SCSS Modules. `components.css` относится к HTML-витрине/макетам; приложение использует `shared/ui`. Демо-скрипты, синтетические цифры, галерейная навигация и неработающие элементы макета не становятся требованиями к продукту автоматически. Проверки Chrome, описанные в документации макетов, относятся к HTML-прототипам, а не к текущему React-приложению.

## Как работать без сервера

Из `frontend/`: `npm ci`, затем `npm run dev:mock`. Клиент — `http://localhost:3000`. Учётки: `smirnov` / `demo123` (клиент), `ivanova` / `demo123` (банк).

MSW включается через `.env.mock` (`VITE_MOCK=true`). Данные изменяются в памяти вкладки и сбрасываются при перезагрузке; сессия хранится в `sessionStorage`. Для просмотра решения от другой роли используйте смену пользователя в той же вкладке: вкладки не разделяют демобазу. В обычном `npm run dev` запросы идут через Vite к серверу.

## Оставшиеся задачи

Это выявленные направления работ, а не утверждение, что весь объём нужно реализовать в ближайшей задаче.

Подробная последовательность работ по визуальному приведению интерфейса к макетам — в [UI_ALIGNMENT_PLAN.md](UI_ALIGNMENT_PLAN.md). План подготовлен 21.10.2026; реализация по нему ещё не начата.

1. Согласовать типы, формы и моки с уточнением о действующих клиентах банка: данные компании/обороты, выбор поручителя, исключение выписки и библиотеки файлов. **Ввод ИНН пока не менять.**
2. Завершить перенос дизайна, прежде всего оболочки и главной. Сохранять визуальную систему и не восстанавливать исключённые бизнес-сценарии.
3. Сверить подписание, печатные формы и ответы на запросы банка с актуальной спецификацией.
4. Для планера отдельно определить объём расширения: редактирование, состояния, правила актуальности рекомендаций и уведомлений. Почтовые уведомления не реализовывать: текущий продукт использует только кабинет.
5. Исправить существующие проблемы проверок без снижения требований; добавить E2E для пути от входа до выдачи после готовности интеграции. Playwright-набора пока нет.
6. По мере готовности сервера проверять сценарии через `deploy/`; не переносить серверную бизнес-логику в UI ради обхода отсутствующих эндпоинтов.
