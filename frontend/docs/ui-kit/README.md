# Умный кредитный кабинет · UI kit 0.1

Дизайн-система кредитного кабинета: автономная HTML-витрина и основа компонентов React. Это рабочая система проекта, а не официальный UI kit Альфа-Банка. Контракт продукта — [API_SPEC.md](../../../docs/API_SPEC.md), состояние реализации — [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md), макеты — [designs/](../designs/README.md).

Исторические источники: исходное ТЗ в PDF, `finance-light-1920x1080.svg`, `finance-dark-1920x1080.svg`, `palettes.md` и `palettes.json`. Эти файлы отсутствуют в текущем дереве репозитория; рабочие токены находятся рядом в `tokens.json` и `tokens.css`.

## Как понят проект

Веб-кабинет малого и микробизнеса объединяет путь от выбора финансирования до решения, принятия условий и моделируемой выдачи. Есть две роли: клиент (`CLIENT`) и сотрудник банка (`BANK_OFFICER`). Клиенту нужны простые пояснения, сохранение введённых данных, понятный статус и следующее действие. Сотруднику — плотные таблицы, документы, результаты проверок и обоснование решения.

Референсы задают характер: светлые или графитовые поверхности, глубокий красный, мягкие тени, скругления и крупные финансовые показатели. Их банковские карты, инвестиции и декоративный логотип не являются требованиями продукта. В UI kit они не переносятся. Обслуживание выданных кредитов и поддержка — расширения из API_SPEC, а не обязательный объём исходного ТЗ.

Базовые компоненты уже реализованы в [src/shared/ui](../../src/shared/ui/index.ts), маршруты — в [app/routes](../../src/app/routes/router.tsx). Перенос композиций из HTML-макетов в React частичный. Загрузка выписки исключена актуальными требованиями.

## Визуальный характер

Спокойный деловой интерфейс с ощущением контроля. Основная площадь нейтральная; красный выделяет основное действие и текущий выбор. На одну логическую область — одно главное действие. Большие суммы, ясная иерархия, умеренная плотность. В рабочих таблицах меньше воздуха, чем в клиентских формах, при тех же токенах.

Светлая тема — исходная. Тёмная равноценна по функциям. Декоративные градиенты допустимы на главной кнопке и редком акцентном блоке; формы, таблицы и текстовые карточки используют сплошные поверхности. Весь экран не следует окрашивать в красный. Реальные условия и результат решения важнее иллюстраций.

## Типографика, размеры и композиция

- Стек: `Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif`. В комплекте нет файла Inter и нет внешней загрузки шрифтов. До добавления локального WOFF2 с кириллицей и лицензией работает системный fallback.
- Заголовок страницы: 32/40 px, 600; на узком экране 28/36. Заголовок секции: 20/28, 600. Заголовок карточки: 16/24, 600.
- Основной текст: 16/24. Компактные строки: 14/20. Подписи: 13/20. Бейдж: 12/18, 600. Не уменьшать текст ради вмещения таблицы.
- Главная сумма: 36/44, 600; дополнительные суммы 24/32. Для сумм и табличных данных — `font-variant-numeric: tabular-nums`.
- Шаг отступов 4 px: 4, 8, 12, 16, 20, 24, 32, 40, 48. Между полями 20–24; между секциями 32–40.
- Скругления: 8 для небольших элементов, 12 для контролов, 24 для карточек, 999 для бейджей.
- Контролы: 48 px; компактные действия в таблицах допустимы от 40 px. Область нажатия иконки — 44 × 44 px.
- Иконки: SVG, 20 или 24 px, обводка 1.5–2 px, `currentColor`. Кнопка только с иконкой требует доступного имени; tooltip не заменяет `aria-label`.
- Анимация 160 ms для hover; без скачков размеров и смещения контента. Учитывать `prefers-reduced-motion`.

Для будущих страниц: основная сетка 12 колонок, gap 24, поля 32 на desktop. Ширина рабочей области до 1440 px; форма обычно 640–760 px с боковой сводкой условий. От 1024 px возможна двухколоночная компоновка, ниже — одна колонка и компактная навигация; до 640 px поля 16. Адаптивный веб не означает отдельное мобильное приложение. На 1920 px интерфейс не масштабируется целиком из SVG: сохраняет читаемые размеры. Таблицы прокручиваются внутри собственного контейнера.

|---|---|---|

| Field | input, select, textarea; default, filled, focus, invalid, disabled, readonly | Постоянная подпись, единицы, подсказка, ошибка под полем. Placeholder не заменяет label |

| StatusBadge | neutral, info, warning, success, danger | Читаемая подпись; цвет дополняет смысл |
| Alert | info, warning, success, danger | Причина и следующее действие; важное сообщение остаётся на странице |
| Stepper | completed, current, upcoming | Этап заполнения отделён от банковского статуса рассмотрения |
| DataTable | sorting, filters, pagination, row action — на этапе страниц | Заголовки колонок, суммы вправо, переход явной ссылкой. На узких экранах свой scroll |
| FileUpload | empty, selected, uploading, success, failed | Допустимые форматы и лимит берутся из контракта, ошибки и удаление файла рядом с ним |
| AsyncState | skeleton, empty, error, retry | Не подменять отсутствие ответа нулевой суммой. При повторной загрузке сохранять известные данные |
| Dialog / Drawer | проектируются при согласовании страниц | Управление фокусом, Escape, возврат фокуса; подтверждение только значимых действий |
| Toast / Notifications | проектируются при согласовании страниц | Не использовать краткий toast как единственное сообщение о решении или запросе банка |

В `components.css` реализован визуальный базис HTML-витрины. Таблица выше описывает дизайн и поведение; фактический состав React-компонентов смотрите в [shared/ui/index.ts](../../src/shared/ui/index.ts). В React уже есть в том числе Modal, DataTable, FileUpload и AsyncBoundary. Витрина — демонстрация на синтетических данных, не прототип кредитного конвейера; наличие файлового компонента не требует загрузки документов в актуальном клиентском сценарии.

## Статусы из API

| API-код | Подпись клиенту | Семантика |
|---|---|---|
| DRAFT | Черновик | neutral |
| SUBMITTED | Заявка отправлена | info |
| DATA_CHECK | Проверяем данные | info |
| INFO_REQUESTED | Нужна информация | warning |
| SCORING | Оцениваем заявку | info |
| ON_DECISION | Принимаем решение | info |
| APPROVED | Одобрено | success |
| COUNTER_OFFER | Предложены другие условия | warning |
| REJECTED | Не одобрено | danger |
| SIGNING | Ожидает подписания | warning |
| ISSUED | Кредит выдан | success |
| CLOSED | Заявка закрыта | neutral |

В кабинете сотрудника допустимы технические подписи «Скоринг» и «На решении». Словарь клиентских подписей — предложение интерфейса; API-коды остаются без изменений. Предварительный STOP внутри DRAFT не превращать в REJECTED. Уточнение информации и иные условия не оформлять как ошибку системы. Итоговую оценку риска не представлять как гарантию выдачи.

## Данные, тексты и доступность

Деньги отображать через `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB', maximumFractionDigits: 0 })`; если появятся копейки, точность задаёт контракт. Значения API в рублях не делить на 100. Ставки: `22,5 % годовых`; срок: `24 месяца`. Часовой пояс отображения дат явно согласовать с приложением; не зашивать дату демонстрации в компоненты.

Автозаполненные сведения компании сопровождать источником и объяснением, как исправить ошибку. Сохранение черновика показывать только после подтверждения сервера. Бизнес-отказ отличать от сбоя: «Не удалось загрузить данные. Повторить». При VERSION_CONFLICT предложить обновить данные с сохранением локального ввода. Не показывать пользователю traceId и банковские коды вместо понятного пояснения; технический идентификатор допустим в раскрываемых деталях ошибки.

Ориентир доступности: контраст текста 4.5:1, крупного текста и значимых контуров 3:1, клавиатурное управление, видимый focus. Проверять реальные сочетания поверхности и текста, включая hover, а не только основные HEX. Декоративный `border` не заменяет контрастный контур поля. Цвет не единственный носитель статуса. Ошибки привязаны через `aria-describedby`, поле — `aria-invalid`; сообщения после действия — через live region. Декоративные иконки скрывать от скринридера. При 200% масштабе не терять действия и текст.

## Файлы и подключение к React

- `index.html`, `preview.css`, `preview.js` — автономная витрина с переключением темы, палитрой, формами и состояниями. Открывается без сборки и интернета.
- `tokens.json` — редактируемые семантические токены; `tokens.css` — CSS для HTML, синхронизируется вручную с JSON и CSS приложения.
- `components.css` — стили HTML-компонентов витрины и макетов; `preview.css` относится только к витрине.
- [src/shared/ui/index.ts](../../src/shared/ui/index.ts) — public API реальных React-компонентов; стили — SCSS Modules рядом с компонентами. Упоминавшегося ранее `react-example.tsx` в репозитории нет.

В текущем приложении токены подключены из `src/app/styles/index.scss`; тема задаётся атрибутом `data-theme` на `document.documentElement` (см. [useTheme.ts](../../src/widgets/client-shell/model/useTheme.ts)). Компоненты импортируются из public API:

```tsx
import { Button } from '@shared/ui';

export const ContinueButton = () => <Button>Продолжить</Button>;
```

Тема должна покрывать фон приложения и portal-контейнеры. Стартовый выбор — сохранённое предпочтение, затем настройка ОС; пользователь может переключить вручную. Витрина реализует этот порядок и сохраняет выбор при доступности localStorage.

## Формат будущих макетов

Предлагается HTML/CSS для интерактивного согласования и React/TSX как итоговая реализация. Это позволяет проверять русский текст, адаптивность, focus, ошибки и реальные состояния. CSS и токены переносятся без переопределения цветов в каждой странице. SVG нужен для иконок, иллюстраций и при необходимости статичных снимков, но не для целых рабочих экранов: в нём неудобно проверять форму и поведение.

Каркас и страницы для двух ролей уже есть в React. Следующая работа — сверять их с актуальным контрактом и завершать перенос дизайна. Карта страниц и известных расхождений — в [контексте проекта](../PROJECT_CONTEXT.md).

## Выполненная проверка

При создании HTML-витрины зафиксирована проверка в локальном Chrome на ширинах 375, 768 и 1440 px: горизонтального переполнения страницы нет; таблица и навигация имеют собственную прокрутку. Проверены смена темы, невалидная/валидная сумма и возврат кнопки из loading; ошибок JavaScript не обнаружено. Светлая и тёмная версии просмотрены визуально. Для основных пар токенов рассчитан контраст: основной/вторичный текст на поверхности, статусы на своих фонах и белый текст на основном акценте — не ниже 4.5:1; контур поля на поверхности — выше 3:1. Это исторический отчёт о витрине, а не новый аудит React-приложения. Актуальные результаты сборки и тестов — в [контексте проекта](../PROJECT_CONTEXT.md#проверки).

## Общие компоненты выбора и подсказок

- `Select` — единый контрол для всех выпадающих списков приложения. `SelectField` добавляет подпись, подсказку и ошибку; `SelectFilter` — обёртку для панели фильтров. Используется собственное меню с ролями `combobox`/`listbox`, клавиатурной навигацией и оформлением токенами темы. Контракт: `options`, `value`, `onChange(value)`; варианты `field`, `filter`, `inline`. Для react-hook-form используется `Controller`.
- `MonthPicker` — выбор месяца и года через `SelectField`, принимает `{ year, month }` (месяц 0–11) и `onChange`. Используется в планере.
- `Tooltip` — краткая текстовая подсказка: `label` задаёт доступное имя кнопки, `content` — пояснение, `children` — необязательный значок. По умолчанию показана иконка информации. Работает при наведении, фокусе и касании, закрывается Escape и кликом снаружи; текст доступен через `aria-describedby`. Portal сохраняет токены темы и не обрезается карточкой.
- `Page.titleAside` — место для поясняющего действия справа от заголовка без изменения текста `h1`.
- `Modal.size` — `small` (до 400 px), `default`, `wide` и `large` (до 1120 px). Старый `wide` сохранён для совместимости; планер использует `large`. `layer="overlay"` поднимает окно над остальными слоями. Нижние диалоги временно получают `inert` и скрываются от скринридера; после закрытия доступность и фокус восстанавливаются. На мобильных окно занимает ширину экрана.
- `MoneyField` — целые рубли с группировкой тысяч пробелами, вставкой и сохранением позиции курсора при редактировании. Принимает `value` без разделителей и `onValueChange`.
- `DateField` — календарь на MIT-библиотеке `@daypicker/react` 10.0.2 с русской локалью и стилями токенов проекта. Поле отображает `ДД.ММ.ГГГГ`, возвращает ISO-день; незавершённый ввод остаётся строкой для валидации. Календарь открывается в отдельном модальном слое через portal поверх интерфейса, не занимает места в форме и не обрезается её прокруткой. Меню месяца/года использует общий `MonthPicker`. Escape последовательно закрывает меню, календарь и основную модалку; выбор даты возвращает фокус к полю. Это поведение действует для всех использований компонента.

Для этих React-компонентов добавлены тесты. Последующие изменения проверяются без запуска браузера по прямому указанию пользователя; историческая проверка HTML-витрины выше не заменяет визуальную проверку текущего интерфейса.

### Выпадающий список в модальных окнах

Общий `Select` выводит список через портал внутрь ближайшего диалога (или `body` вне диалога) и нативный
Popover API в верхний слой браузера. Меню не участвует в размерах модального окна и не обрезается его прокруткой.
Положение привязано к полю и обновляется при прокрутке и изменении размеров; направление и высота зависят от
свободного места видимой области экрана. Длинный список прокручивается самостоятельно. Фокус остаётся на поле:
стрелки выбирают пункт, Escape закрывает список, Tab продолжает навигацию по форме. Изменение от 24.10.2026
не проверялось браузером, тестами или сборкой по указанию пользователя.
