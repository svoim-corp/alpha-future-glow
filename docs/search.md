# Общий поиск клиентского кабинета

Реализовано на клиенте и сервере 24.10.2026. Поиск доступен CLIENT с компанией; область определяется сессией. Заявки, кредиты и планы — своей компании; обращения — своего пользователя. Каталог и FAQ — публичные данные. Банк в этот сценарий не входит.

## Запрос

`GET /api/v1/search?q=...&limitPerType=3&types=plans&cursor=...`

- `q`: после нормализации пробелов, регистра и ё/е — 2–120 символов. Управляющие символы запрещены. Пустой запрос не выполняется клиентом.
- `types`: необязательный список через запятую: `applications,loans,plans,products,faq,tickets`; по умолчанию все.
- `limitPerType`: 1–20, по умолчанию 3.
- `cursor`: непрозрачная позиция следующей страницы, только с одной категорией. Привязан к запросу, категории и области доступа. Порядок: качество совпадения по убыванию, ID по возрастанию. Изменение объекта может изменить его положение между чтениями; снимок выдачи не сохраняется.

Ответ 200: `{query, groups:[{type,items:[{id,title,snippet,state,step}],hasMore,nextCursor,unavailable}]}`. `state` и `step` — строки, пусты когда неприменимы. `nextCursor` — строка или null. Неуспех источника: пустые items, unavailable=true, не трактуется как отсутствие совпадений. Если недоступны все источники — 503 SEARCH_UNAVAILABLE в общем формате ошибки. 400 — неверные параметры/курсор, 401 — нет сессии, 403 — нет клиентского доступа.

Точное совпадение ID/номера выше точного названия, затем префикс названия, затем вхождение в текст и русский полнотекстовый поиск. Символы LIKE экранируются; SQL-параметры связаны, HTML в выдаче отсутствует. Удалённые черновики исключаются; закрытые кредиты и архивные планы доступны с состоянием. Общее число не вычисляется: достаточно hasMore.

## Архитектура

Search объединяет ограниченные запросы провайдеров зон через shared-контракты. Каждая зона читает только свою схему и применяет доступ до поиска. Зоны подключаются в cmd/api/main.go. Каталог предоставляет словарь названий продуктов и целей через отдельный порт для поиска в заявках и планах. Общие функции нормализации — platform/searchtext. SQL и индексы принадлежат доменным зонам. На источник даётся ограниченное время; запросы выполняются параллельно, отменяются с HTTP-контекстом и завершаются до выхода из обработчика.

На клиенте entities/search содержит DTO и RTK Query; features/global-search — управление вводом, подсказки, результаты и маршрутизацию; pages/search — полный поиск; ClientShell размещает фичу. Серверные ответы остаются в RTK Query. Ключ кеша учитывает пользователя/компанию, сбрасывается при выходе. Debounce 300 мс, старые ответы не показываются под новым запросом. Без выбора Enter открывает /search?q=..., стрелки выбирают результат, Escape закрывает подсказки. На телефоне панель занимает доступную ширину и высоту.

## Открытие результатов

- Заявка: существующие маршруты деталей либо редактирования черновика.
- Кредит: `/credits?loan=ID&tab=active|closed`.
- План: `/planner?plan=ID`, независимый `GET /plans/{id}` своей компании, включая архив.
- Продукт: `/products?product=CODE`, существующие условия продукта.
- FAQ: `/support?faq=ID`, отдельное чтение вопроса через `GET /support/faq/{id}`.
- Обращение: `/support?ticket=ID`, `GET /support/tickets/{id}` своего пользователя.

Новые GET по ID возвращают 404 для отсутствующего и чужого объекта одинаково. План возвращает тот же DTO с рекомендацией, что список; вопрос — тот же DTO FAQ; обращение — тот же DTO списка. Эти чтения не зависят от ограничений старых списков. Закрытие окна удаляет соответствующий параметр URL. Поиск не создаёт заявку, не меняет объект и не отмечает уведомления прочитанными. Отдельная история запросов не ведётся. Полный поиск отражается в URL и обычной истории навигации браузера.

## Запуск и проверка

После обновления кода нужно перезапустить API: goose применит новые индексы пяти доменных схем. Данные не сбрасываются. Новые зависимости приложения не добавлены; Swagger сгенерирован из обработчиков.

Браузерную и сквозную проверку пользователь выполняет самостоятельно. Тесты по прежнему указанию пользователя не добавлялись и не запускались. Результаты статических проверок и сборки фиксируются в сообщении задачи; наличие API не подтверждает проверку миграций на пользовательской БД.
