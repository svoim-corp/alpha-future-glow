# Servicing — кредиты и платежи

Зона Servicing (`backend/internal/servicing`, разработчик A): выданные кредиты, график платежей, платёжный календарь,
напоминания о платежах. Схема БД — `servicing`. ТЗ заканчивает путь выдачей, обслуживание — допущение команды.

Постановка дальнейших доработок — [серверные задачи обслуживания](servicing-backend-tasks.md): оплаты, досрочное погашение и закрытие, полная задолженность, пагинация и PDF графика. Это проект нового контракта для согласования; описанные там новые запросы пока не реализованы. Ниже зафиксирован текущий API.

## Кредит и график

Реализовано. Кредит заводится при выдаче (`POST /applications/{id}/contract/disburse`, зона Offer) через
`shared.Loans.Open`, один на заявку: повторная выдача возвращает уже заведённый кредит (`l-<номер>`).

- Условия — из подписанного договора: сумма, срок, ставка, отсрочка, номер договора `КД-…`. Название продукта
  сохраняется в кредите.
- График аннуитетный. Проценты месяца — на остаток долга по ставке / 12, округление до рубля. В отсрочку — только
  проценты. Затем равные платежи (`monthlyPayment` = аннуитет на `срок − отсрочка` месяцев); последний платёж гасит
  остаток, поэтому сумма основного долга равна сумме кредита до рубля.
- Дата n-го платежа — то же число, что и дата выдачи, через n месяцев; в коротком месяце — последний день
  (31 января → 28 февраля).
- Платежей в демо не бывает: строки графика `PLANNED`.

## API

Все эндпоинты — для клиента: он видит кредиты своей компании; сотрудник банка — `403`, чужой кредит — `404`.
Даты — `YYYY-MM-DD`. Статус платежа в ответах: `PLANNED`, `PAID` или `OVERDUE` — неоплаченный платёж с прошедшей
датой (вычисляется при чтении, «сегодня» — по UTC).

### `GET /loans/summary`

Реализовано. Для главной: число действующих кредитов и ближайший платёж — дата ближайшего неоплаченного платежа
(сегодня или позже) и сумма всех платежей компании в эту дату. Платежей впереди нет — `nextPayment: null`.

```json
{ "activeLoans": 1, "nextPayment": { "date": "2026-11-20", "amount": 61958 } }
```

### `GET /loans`

Реализовано. Выданные кредиты компании, новые первыми.

```json
[
  {
    "id": "l-55",
    "product": { "code": "WORKING", "name": "Оборотный кредит" },
    "amount": 1200000,
    "balance": 1200000,
    "rate": 21.5,
    "term": 24,
    "issuedAt": "2026-10-20",
    "nextPayment": { "date": "2026-11-20", "amount": 61958 },
    "status": "ACTIVE"
  }
]
```

- `balance` — сумма кредита минус оплаченный основной долг.
- `nextPayment` — первый неоплаченный платёж сегодня или позже; просроченные видны в графике (`GET /loans/{id}`).
  Платежей впереди нет — `null`.

### `GET /loans/{id}`

Реализовано. Условия договора и полный график. Чужой или несуществующий кредит — `404` (существование кредитов
других компаний не раскрывается).

```json
{
  "id": "l-55",
  "applicationId": "a-1031",
  "contractNumber": "КД-2026-0055",
  "product": { "code": "WORKING", "name": "Оборотный кредит" },
  "balance": 1200000,
  "issuedAt": "2026-10-20",
  "status": "ACTIVE",
  "terms": { "amount": 1200000, "term": 24, "rate": 21.5, "graceMonths": 0, "monthlyPayment": 61958 },
  "payments": [
    { "date": "2026-11-20", "principal": 40458, "interest": 21500, "total": 61958, "status": "PLANNED" }
  ]
}
```

### `GET /loans/schedule?from=2026-11-01&to=2026-12-31`

Реализовано. Платежи всех кредитов компании за период (обе даты включительно), по датам. `from` и `to` обязательны,
формат `YYYY-MM-DD`, `to` не раньше `from`, период — не больше года; иначе `400 VALIDATION_ERROR`.

```json
[
  { "date": "2026-11-20", "loanId": "l-55", "productName": "Оборотный кредит", "amount": 61958, "status": "PLANNED" },
  { "date": "2026-12-20", "loanId": "l-55", "productName": "Оборотный кредит", "amount": 61958, "status": "PLANNED" }
]
```

### `GET /loans/schedule/upcoming?limit=3`

Реализовано. Ближайшие неоплаченные платежи всех кредитов компании — сегодня и позже, ближайшие первыми. Формат
элементов тот же, что у `GET /loans/schedule`. `limit` — от 1 до 12, по умолчанию 3; иначе `400`.

## Напоминания о платежах

Реализовано. Фоновый воркер (`Module.Run`, запускается из `cmd/api` и останавливается вместе с сервером) сразу при
старте и затем раз в час ищет неоплаченные платежи действующих кредитов со сроком от сегодня до +3 дней и
отправляет заявителю уведомление `PAYMENT_DUE`:

- заголовок «Платёж по кредиту 20.11.2026», текст «61 958 ₽ по договору КД-2026-0001 («Оборотный кредит»)»,
  ссылка `/credits/calendar`;
- одно напоминание на платёж: отметка `reminded_at` ставится атомарно до отправки; если уведомление не ушло,
  отметка снимается и следующий проход повторит;
- просроченные платежи не напоминаются — они видны в графике со статусом `OVERDUE`.

В демо кредит выдаётся «сегодня», поэтому первое напоминание придёт за 3 дня до первого платежа через месяц.

## Клиентские страницы кредитов

Обновлено 22.10.2026. Изменения сделаны только на клиенте под существующий API; сервер и клиентские моки не менялись.

- `/credits` показывает действующие и закрытые кредиты с серверными статусами. Закрытый кредит не получает подписи и подсказки действующего. Остаток и условия уточняются по ответу деталей кредита.
- Под вкладками «Действующие», «Одобренные» и «Закрытые» расположена горизонтальная лента компактных карточек с названием, суммой и идентификатором кредита или номером заявки. При первом открытии вкладки выбран первый элемент в порядке сервера; ниже показаны только его детали. Сделанный пользователем выбор сохраняется отдельно для каждой вкладки на время нахождения на странице. Если выбранная запись исчезает после обновления, показывается первая доступная. Выбранная карточка выделена цветом и галочкой, доступна с клавиатуры и при выборе прокручивается в видимую часть ленты. Сводные суммы сверху относятся ко всем полученным кредитам и предложениям, а не к выбранному элементу. Названия предложенных продуктов уточняются через существующий каталог; если банк поменял продукт, название из исходной заявки не выдаётся за название предложения.
- Плитка «Ближайший платёж» складывает платежи только одной, ближайшей даты. Просроченные строки показываются отдельно с суммой основного долга и процентов по графику, без предположений о пенях. Дата, сумма и разбивка будущего платежа берутся из одной строки графика.
- Диаграмма показывает до шести будущих платежей; просрочка не подставляется вместо будущего платежа. Подсказки доступны при наведении, фокусе клавиатуры и касании. В таблице доступны полный график, ближайшие будущие, оплаченные и просроченные платежи. Полный график можно выгрузить в CSV на клиенте.
- Окно «Условия и документы кредита» показывает данные договора, дату выдачи, отсрочку и печатные формы банка через существующий `GET /applications/{id}/contract`. Печатные формы — HTML, а не серверные PDF-файлы графика.
- Предложения загружаются независимо от кредитов: клиент проходит все страницы списка заявок и запрашивает условия `APPROVED`, `COUNTER_OFFER` и `SIGNING`. Запросы собраны в API сущности заявки через RTK Query; ошибки загрузки списка и отдельных условий имеют повтор. Сумма одобрений вычисляется по `offered.amount`, без подстановки запрошенных сумм. Если часть условий не загрузилась, общий итог не показывается. Истёкшие непринятые предложения отмечаются и не включаются в сумму; принятые предложения остаются видны до выдачи.
- При возврате на страницу, фокусе окна и восстановлении соединения данные обновляются; ручное обновление перечитывает список и детали кредитов. Блок полезных ссылок доступен и на узких экранах, размеры мелких подписей увеличены.
- `/credits/calendar` использует серверный график, русский выбор месяца и года, возврат к сегодняшнему дню по UTC, статусы платежей и список выбранной даты. Вся карточка даты — кнопка выбора, доступная с клавиатуры; текущая и выбранная даты выделены. Компактные ячейки имеют одинаковую фиксированную высоту: внутри показан только первый платёж в порядке серверного ответа, остальные обозначены подписью «Ещё N платежей» с нужным склонением. Все платежи выбранного дня, их точные суммы и статусы доступны под календарём. Сетка занимает доступную ширину без горизонтальной прокрутки; на узких экранах скрыто название продукта, подпись сокращается до «+N», а на телефонах первый платёж обозначен цветным индикатором. Пока новый месяц загружается, платежи прежнего месяца не показываются под новым заголовком.

### Ограничения сервера

Нет клиентских команд оплаты, учёта частичного или досрочного погашения, перерасчёта графика и перевода кредита в `CLOSED`. Нет данных о пенях и полной сумме просроченной задолженности с начислениями. Отдельной серверной выгрузки полного графика в PDF нет; клиент предлагает CSV и доступные печатные формы договора.

`GET /loans` ограничен 100 кредитами без пагинации и общего количества. При достижении этой границы клиент предупреждает о возможной неполноте и скрывает общие суммы. Сводный список офферов отсутствует, но его можно получить на клиенте через существующую пагинацию заявок и запросы условий.

По указанию пользователя браузер, тесты, сборка и автоматические проверки этих изменений не запускались. Сквозная работа на пользовательском окружении и визуальная проверка остаются за пользователем.
