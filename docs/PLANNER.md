# Календарь и планер: текущая клиентская реализация

Обновлено 21.10.2026. Описывает реализованный клиент `/planner`; сервер в рамках этой доработки не изменялся.

## Сценарий

Внешний вид основан на `frontend/docs/designs/planner.html`: сводные карточки, календарь, общая палитра и обе темы. По последующим запросам пользователя убраны вводный баннер и подпись над заголовком; просмотр планов перенесён в модальные окна.

При открытии календарь показывает текущий московский месяц. Календарь занимает всю ширину, список планов выбранного дня расположен под ним и включает все пересечения периодов. Выбор плана открывает широкое модальное окно деталей. В списках вся карточка открывает диалог, в том числе с клавиатуры. Идеи без даты доступны отдельной вкладкой и не получают искусственную дату.

Календарь поддерживает прямой выбор месяца и года, переключение месяцев стрелками, соседние дни сетки и возврат к «Сегодня». Число в ячейке показывает количество планов; на узком экране названия убираются из ячеек, а полный список выбранного дня остаётся доступен ниже. При переключении месяца или дня прежние детали закрываются. Кнопки доступны с клавиатуры, выбранная дата и текущий день имеют отдельные состояния.

У заголовка страницы доступна краткая подсказка по наведению, фокусу и касанию. Три карточки сводки расположены в начале страницы вместо вводного баннера.

Есть представления «Календарь», «Все планы», «Идеи без даты» и «Архив». В рабочих представлениях доступен фильтр состояния; его место сохраняется и в архиве, где фильтр скрыт и недоступен для фокуса. Сводка при загрузке сохраняет плитки с прочерками, чтобы панель вкладок не смещалась; во вкладке архива запрашивается только `state=ARCHIVED`. Сводка показывает данные ответа сервера для текущего представления и фильтра, а не бюджет только выбранного дня.

## Даты и состояния

Правила клиента согласованы с кодом `backend/internal/planner/`:

- `DAY`: обязательна дата начала, конец равен началу.
- `PERIOD`: начало и конец обязательны, конец не раньше начала; обе границы включены.
- `UNSCHEDULED`: даты отсутствуют.
- Календарные даты передаются строками `YYYY-MM-DD`, без сдвига из-за часового пояса устройства.
- Для определения «Сегодня» используется фиксированный UTC+3, как в текущем серверном демо-контракте. Клиент обновляет определение дня раз в минуту, пока страница открыта.
- Состояния — `ACTIVE`, `PAUSED`, `DONE`, `ARCHIVED`. Их можно изменить в деталях существующей серверной командой `PATCH`.
- Положение периода во времени отображается отдельно от сохранённого состояния. Прошедший период не переводит план в `DONE` автоматически.
- По умолчанию список исключает архив. Архив и остальные состояния открываются фильтром `state`.

## Формы и команды

Клиент использует существующие `GET /plans`, `POST /plans`, `PATCH /plans/:id`, `DELETE /plans/:id` под `/api/v1`.

Все запросы и мутации планов объединены в `entities/plan/api/planApi.ts`, типы запросов находятся в модели сущности. Формы и пользовательские действия в `features/manage-plans` используют хуки через публичный API `@entities/plan`.

Форма создания, редактирования и просмотр используют отдельный размер `Modal size="large"` шириной до 1120 px. На большом экране форма и детали имеют две колонки, на узком — одну. Просмотр, редактирование и подтверждение удаления показывают по одному диалогу; отмена действия возвращает к просмотру. Название обязательно, до 200 символов; цель вводится свободным текстом, обязательна, до 64 символов; заметка необязательна, до 2000. Внешние пробелы цели удаляются.

Бюджет отображается с пробелами между разрядами (`1 200 000`), внутри формы хранится строкой цифр и отправляется как целое число рублей. `MoneyField` поддерживает вставку суммы с пробелами и редактирование в середине. Клиент отклоняет значения вне безопасного целочисленного диапазона JavaScript, чтобы не отправить округлённую сумму.

В полях начала и окончания используется общий `DateField` на `@daypicker/react` 10.0.2: русский формат `ДД.ММ.ГГГГ`, ручной ввод, календарь с выбором месяца и года, клавиатурное управление и токены обеих тем. В API по-прежнему передаются календарные строки `YYYY-MM-DD` без смещения часового пояса. Браузерный `input type="date"` не используется.

Календарь поля даты открывается отдельным модальным окном поверх формы через portal, без сдвига её содержимого. Пока календарь открыт, нижняя форма недоступна для взаимодействия. Выбор даты, Escape, кнопка закрытия или нажатие вне окна закрывают календарь. Новые тесты и проверки по указанию пользователя не выполнялись.

В списке выбранного дня без планов есть кнопка «Создать новый план»: форма открывается в режиме одного дня с этой датой. Верхняя кнопка «Новый план» по-прежнему открывает идею без даты.

Создание отправляет нормализованные даты. Редактирование передаёт только изменённые поля: пустая заметка очищается строкой `""`, даты сбрасываются сменой режима на `UNSCHEDULED`. Неизменённый email-флаг не перезаписывается. После успешных команд RTK Query перечитывает списки и сводку; ошибка не выдаётся за успешно применённое изменение.

Ошибки полей из API показываются в форме, остальные — общим сообщением. При ошибке введённое сохраняется. Повторное сохранение во время запроса заблокировано; форму нельзя закрыть во время сохранения. При закрытии изменённой формы предлагается продолжить ввод или отказаться от несохранённых изменений.

Удаление требует подтверждения и отличается от архивирования. Сервер физически удаляет запись: корзины и получения удалённых планов нет. Предупреждение об этом показано в подтверждении и во вкладке архива. Архивированный план можно вернуть в работу сменой состояния. После удаления выбранного плана его устаревшие детали больше не отображаются.

## Границы интеграции

Форма не запрашивает справочник целей и не блокируется при его недоступности. Сервер принимает произвольную строку `goal` до 64 символов без проверки принадлежности справочнику. Однако `Catalog.ProductMatcher()` сопоставляет цель с кодами каталога: свободный текст может сохраниться без рекомендации. Клиент не пытается угадывать код или менять серверную логику.

Подбор финансирования не вычисляется на клиенте. Сервер возвращает один подходящий продукт, а не список. По последнему решению пользователя в окне оставлены только название, описание кредита и неактивная кнопка «Перейти к оформлению» с пояснением, что страница пока недоступна. Ввод срока, требования, расширенные условия и создание черновика из планера убраны. Нажатие кнопки не выполняет запрос и не меняет маршрут. При ошибке описания есть повтор загрузки; отсутствие рекомендации не заменяется произвольным продуктом. Наличие рекомендации не является решением банка.

Форма показывает только настройку уведомлений в кабинете. Она сохраняет предпочтение; реальная доставка в рамках клиентской доработки не проверялась. Внешний канал и отправка писем не реализовывались.

## Демо и проверка

Браузерный MSW поддерживает создание, изменение, удаление, фильтры и нормализацию дат. Новые планы не получают выдуманную рекомендацию. Данные демо хранятся в памяти вкладки и сбрасываются при перезагрузке; это не серверное сохранение в PostgreSQL.

Клиентские сценарии проверяются с настоящим RTK Query и MSW, а правила дат и подготовки PATCH — отдельными тестами. Демообработчики также покрыты HTTP-тестами. В браузере проверены создание периода, выбор плана, изменение бюджета, desktop 1440 px и мобильная ширина 390 px, светлая и тёмная темы, выбор дня с клавиатуры через Tab и Enter.

Для последующих изменений интерфейса (месяц/год, подсказка, единые селекты и создание из пустого дня) автоматические проверки прошли; визуальная проверка не завершена из-за недоступности инструмента управления браузером.

Работа UI с настоящим Go API и БД в этой доработке не подтверждена. Неработающие внешние зависимости не исправлялись расширением серверных модулей.

Остаётся проверить в тестовом окружении:

- Чтение, создание, редактирование, смену состояний и удаление через Go API и PostgreSQL. Перед проверкой подтвердить, что окружение не содержит нужных пользовательских планов; существующую базу автоматически не сбрасывать.
- Сохранение данных после перезагрузки клиента и изоляцию планов разных компаний.

Изменения модальных окон, оформления по рекомендации и архива ранее проходили автоматические проверки без запуска браузера. После запрета пользователя новые тесты и проверки не выполнялись, включая последние изменения кнопки удаления и модального календаря. Сервер не менялся.
