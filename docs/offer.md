# Offer & Contract — предложение, подписание, выдача

Зона Offer (`backend/internal/offer`, разработчик A): предложение банка по решению, принятие или отказ клиента,
договор и его печатные формы, имитация подписи и выдачи. Схема БД — `offer`.

## Предложение по решению

Реализовано. Решение принимает Scoring (авто) или сотрудник через Underwriting; Scoring публикует `DecisionMade`.
Offer по событию читает решение (`shared.Decisions.LatestDecision`) и заявку и сохраняет предложение. Повторное
событие или новое решение по той же заявке перезаписывает предложение. Уведомление клиенту о решении отправляет
Underwriting, Offer его не дублирует.

- Условия — из решения: продукт, сумма, срок, ставка. Запрошенные — из заявки.
- Ежемесячный платёж — аннуитет по ставке решения; если клиент выбрал отсрочку, долг гасится за `срок − отсрочка`
  месяцев.
- Срок действия предложения — 7 дней с даты решения (`validUntil`, дата в UTC).
- Пояснение для клиента (`explanation` / `reason`). Сотрудник пишет причину для клиента, она показывается как есть.
  Причина авторешения техническая (в ней балл скоринга), поэтому клиенту вместо неё показывается: при отказе —
  «Заявка не прошла автоматическую оценку кредитоспособности», при иных условиях — «Условия подобраны по результатам
  оценки кредитоспособности», при одобрении — без пояснения (`null`).

## API

Все эндпоинты — для клиента своей компании: чужая заявка — `403`, нет заявки — `404`, сотрудник банка — `403`.
Даты без времени — `YYYY-MM-DD`, время — ISO 8601 в UTC.

### `GET /applications/{id}/offer`

Реализовано. Решение и предложение. До решения — `404 NOT_FOUND`.

Одобрено или иные условия:
```json
{
  "decision": "COUNTER_OFFER",
  "requested": { "productCode": "WORKING", "amount": 1500000, "term": 24 },
  "offered": { "productCode": "WORKING", "amount": 1200000, "term": 24, "rate": 21.5, "monthlyPayment": 61958 },
  "explanation": "Сумма снижена по уровню долговой нагрузки",
  "validUntil": "2026-10-27"
}
```
У одобрения на запрошенных условиях `explanation` нет. Отказ:
```json
{ "decision": "REJECTED", "reason": "Заявка не прошла автоматическую оценку кредитоспособности", "alternatives": [{ "productCode": "EXPRESS", "maxAmount": 600000 }] }
```

### `POST /applications/{id}/offer/accept`

Реализовано. Клиент принимает одобрение или иные условия. Тела нет. Договор получает номер `КД-<год>-<номер>`,
заявка переходит `APPROVED/COUNTER_OFFER → SIGNING` (действие `OFFER_ACCEPT`).

Ответ `200`:
```json
{ "status": "SIGNING", "redirect": "/applications/a-1031/sign" }
```

- `409 INVALID_TRANSITION` — отказ (принимать нечего), предложение уже принято или заявка не в статусе решения.
- `422 BUSINESS_RULE` — срок действия истёк: предложение действует по `validUntil` включительно.
- Принятие записывается до перехода статуса; если переход не удался, принятие откатывается.

### `POST /applications/{id}/offer/decline`

Реализовано. Клиент отказывается от одобрения или иных условий. Заявка переходит в `CLOSED` (действие
`OFFER_DECLINE`), причина — комментарий в истории заявки для банка.

Запрос:
```json
{ "reason": "Нашли финансирование в другом месте" }
```
Ответ `200`:
```json
{ "status": "CLOSED" }
```

Без причины — `400`. Отказ банка, уже принятое предложение или повторный отказ — `409`.

### `GET /applications/{id}/contract`

Реализовано. Итоговые условия и документы к подписанию. Есть после принятия предложения, до этого — `404`.

```json
{
  "number": "КД-2026-0001",
  "terms": { "productCode": "WORKING", "amount": 1200000, "term": 24, "rate": 21.5, "monthlyPayment": 61958, "firstPaymentDate": "2026-11-20" },
  "documents": [
    { "id": "d-1", "title": "Кредитный договор", "url": "/api/v1/applications/a-1031/contract/documents/d-1" },
    { "id": "d-2", "title": "Договор поручительства", "url": "/api/v1/applications/a-1031/contract/documents/d-2" }
  ],
  "signed": false,
  "disbursed": false
}
```

- Договор поручительства (`d-2`) — только у ООО с выбранным поручителем.
- `firstPaymentDate` — через месяц после выдачи (то же число, в коротком месяце — последний день). До выдачи —
  через месяц от сегодня: ориентир для клиента.

### `GET /applications/{id}/contract/documents/{docId}`

Реализовано. Печатная форма документа, сформированная банком по условиям принятого предложения: `200`,
`text/html; charset=utf-8`, `Content-Disposition: inline` — фронт открывает её в новой вкладке. Это не библиотека
файлов клиента.

- `d-1` — кредитный договор, `d-2` — договор поручительства (только если он есть в составе договора).
- В форме: номер и дата договора, заёмщик (название и ИНН из данных банка), поручитель (ФИО из данных банка), продукт,
  сумма, срок, ставка, отсрочка, платёж, дата первого платежа; после подписи — отметка о простой электронной подписи.
  Формат — допущение команды, юридической силы не имеет.
- Документа нет в составе договора или предложение не принято — `404`.
