# Notifications — уведомления в кабинете

Зона Notifications (`backend/internal/notifications`, разработчик A, сквозная): уведомления внутри кабинета вместо SMS
и почты. Схема БД — `notifications`.

Уведомления создают другие зоны через `shared.Notifier`. Получатель — пользователь (`userId`), а не компания:
уведомление о заявке получает её заявитель.

| `type` | Кто создаёт | Когда |
|---|---|---|
| `INFO_REQUESTED` | Underwriting (B) | сотрудник запросил пояснения |
| `DECISION` | Underwriting (B) | по заявке принято решение (авто или сотрудником) |
| `PAYMENT_DUE` | Servicing (A) | скоро платёж по кредиту |
| `PLAN_MATCH` | Planner (B) | для плана нашёлся продукт |
| `TICKET_REPLY` | — | зарезервирован: ответов на обращения пока нет (открытый вопрос в `backend/TASKS.md`) |

## Для других зон

### `shared.Notifier`

Реализовано. `Notify(userId, notification)` сохраняет непрочитанное уведомление с id `n-<номер>` и временем создания.
Ошибка сохранения возвращается вызывающей зоне; зоны-потребители сами решают, отменять ли из-за неё своё действие
(Underwriting и Planner только логируют).

`POST /admin/seed/reset` удаляет все уведомления.

## API

Доступно любому вошедшему пользователю; каждый видит только свои уведомления.

### `GET /notifications?unread=true`

Реализовано. Последние 50 уведомлений, новые первыми. `unread=true` — только непрочитанные. `unreadCount` — число
всех непрочитанных, независимо от фильтра и лимита.

```json
{
  "unreadCount": 2,
  "items": [
    {
      "id": "n-15",
      "type": "INFO_REQUESTED",
      "title": "Банку нужны пояснения по заявке",
      "text": "Уточните фактический адрес склада",
      "link": "/applications/a-1024",
      "read": false,
      "createdAt": "2026-10-20T12:40:00Z"
    }
  ]
}
```
