# Catalog — линейка продуктов

Зона Catalog (`backend/internal/catalog`, разработчик A): продукты и их рамки, цели кредита, подбор по задаче,
калькулятор платежа. Схема БД — `catalog`, линейка — seed-миграция `0002_seed.sql`.

Каталог открыт без входа (`r.Public`): клиент смотрит продукты до того, как решит оформить заявку.
Это допущение команды из открытого вопроса в `backend/TASKS.md`; при ответе фронта «только после входа» роуты
переносятся в `r.Client`.

## Линейка (seed)

| Код | Название | Сумма, ₽ | Срок, мес. | Ставка, % | Отсрочка | Поручитель для ООО |
|---|---|---|---|---|---|---|
| `WORKING` | Оборотный кредит | 300 000 – 10 000 000 | 3–36 | 20–28 | нет | да |
| `INVEST` | Инвестиционный кредит | 1 000 000 – 30 000 000 | 12–84 | 18–26 | до 6 мес. | да |
| `EXPRESS` | Экспресс-кредит | 100 000 – 1 000 000 | 3–24 | 24–30 | нет | нет |
| `OVERDRAFT` | Овердрафт | 100 000 – 5 000 000 | 12 | 22–30 | нет | нет |

Допущения:
- У овердрафта срок — 12 месяцев действия лимита, а не «без срока»: тогда скоринг, решение и график платежей
  работают с ним так же, как с кредитом. Признак `revolving` (внутренний, в API не отдаётся) разрешает заявке
  параметр `overdraftLimit`.
- Лимит этапа 1 считает Scoring одинаково для всех продуктов (15% годового оборота по счетам), поэтому `limitRule`
  у всех продуктов одинаковый.

## API

### `GET /products`

Реализовано. Карточки каталога в порядке показа.

```json
[
  {
    "code": "WORKING",
    "name": "Оборотный кредит",
    "shortText": "Закупки, зарплата, налоги, аренда",
    "goals": ["WORKING_CAPITAL"],
    "amount": { "min": 300000, "max": 10000000 },
    "term": { "min": 3, "max": 36 },
    "rate": { "min": 20, "max": 28 }
  }
]
```

### `GET /products/{code}`

Реализовано. Все условия продукта для панели «Условия». `graceMaxMonths` и `requirements.minBusinessAgeMonths` —
`null`, если отсрочки или требования нет. `whatYouNeed` перечисляет только действия клиента: данные компании и обороты
банк берёт сам. Неизвестный код — `404 NOT_FOUND`.

```json
{
  "code": "INVEST",
  "name": "Инвестиционный кредит",
  "shortText": "Оборудование, помещение и развитие бизнеса",
  "description": "Оборудование, помещение, расширение бизнеса. Можно взять отсрочку по основному долгу до 6 месяцев.",
  "goals": ["EQUIPMENT", "REAL_ESTATE", "EXPANSION"],
  "amount": { "min": 1000000, "max": 30000000 },
  "term": { "min": 12, "max": 84 },
  "rate": { "min": 18, "max": 26 },
  "graceMaxMonths": 6,
  "requirements": { "minBusinessAgeMonths": 12, "guarantorForLlc": true },
  "limitRule": "До 15% годового оборота по счетам в банке",
  "whatYouNeed": ["Согласие на запрос в БКИ", "Для ООО — поручитель из руководителя или учредителей и его согласие на запрос в БКИ"]
}
```

### `GET /products/goals`

Реализовано. Цели для блока «Подбор по задаче» в порядке показа: `WORKING_CAPITAL`, `EQUIPMENT`, `CASH_GAP`,
`REAL_ESTATE`, `EXPANSION`.

```json
[
  { "code": "WORKING_CAPITAL", "name": "Пополнить оборотные средства" },
  { "code": "EQUIPMENT", "name": "Купить оборудование" },
  { "code": "CASH_GAP", "name": "Закрыть кассовый разрыв" }
]
```

### `POST /products/match`

Реализовано. Подбор по задаче: для каждого продукта — подходит ли он и почему. Подходящие — первыми, внутри групп
порядок каталога. Проверки по очереди: цель → сумма → срок; причина — первая не пройденная. `term` необязателен:
0 или отсутствие поля — срок не проверяется. Неизвестная цель — `400 VALIDATION_ERROR` по полю `goal`.

Запрос:
```json
{ "goal": "WORKING_CAPITAL", "amount": 1500000, "term": 24 }
```
Ответ `200`:
```json
[
  { "code": "WORKING", "fits": true, "reason": "Подходит по цели, сумме и сроку" },
  { "code": "INVEST", "fits": false, "reason": "Не подходит для цели «Пополнить оборотные средства»" },
  { "code": "EXPRESS", "fits": false, "reason": "Сумма больше 1 000 000 ₽" },
  { "code": "OVERDRAFT", "fits": false, "reason": "Не подходит для цели «Пополнить оборотные средства»" }
]
```

### `POST /calculator/payment`

Реализовано. Калькулятор под суммой и сроком. Ставку до проверки банк не знает, поэтому платёж — диапазон по ставкам
продукта (`rate.min` … `rate.max`). Платёж аннуитетный, округлён до 100 ₽.

- `graceMonths` необязателен. При отсрочке клиент `graceMonths` месяцев платит только проценты (`gracePayment`),
  затем долг гасится аннуитетом за оставшиеся `term − graceMonths` месяцев. Без отсрочки `gracePayment` — `null`.
- `withinProductLimits` — сумма и срок в рамках продукта, отсрочка не длиннее `graceMaxMonths` и короче срока.
  Расчёт отдаётся и вне рамок: калькулятор подсказывает, а не запрещает.
- Неизвестный продукт — `404 NOT_FOUND`; без суммы или срока — `400 VALIDATION_ERROR`.

Запрос:
```json
{ "productCode": "INVEST", "amount": 6000000, "term": 60, "graceMonths": 6 }
```
Ответ `200`:
```json
{
  "rate": { "min": 18, "max": 26 },
  "payment": { "min": 162900, "max": 189600 },
  "gracePayment": { "min": 90000, "max": 130000, "months": 6 },
  "withinProductLimits": true
}
```

## Для других зон

### `shared.Products`

Реализовано. `Product(code)` — рамки продукта из линейки; неизвестный код — `(nil, nil)`. Используют Origination
(рамки при создании и изменении черновика), Offer, Scoring, Underwriting, Planner.

### `shared.ProductMatcher`

Реализовано. `Match(goal, amount)` — продукты с целью `goal`, в рамки суммы которых укладывается `amount`. Срок
Планер не задаёт и не проверяется. Порядок: меньшая минимальная ставка — первой, при равной — порядок каталога.
Пустой список — подходящих нет. Использует Planner.

## Клиентский каталог `/products`

Обновлено 21.10.2026. Клиент использует существующие методы Catalog и создание черновика Origination. Сервер и клиентские моки в этой доработке не изменялись; ориентир — работа с настоящим сервером.

- Композиция соответствует `frontend/docs/designs/catalog.html`: баннер, цели, карточки, калькулятор, помощь и окно условий. На узком экране карточки и колонки окна идут последовательно; используются токены обеих тем.
- Цели и условия берутся из API. Выбор цели ограничивает продукты в калькуляторе; если прежний продукт не поддерживает цель, выбирается доступный продукт этой цели. Несовместимая цель не отправляется при оформлении.
- Подбор выполняется сервером по цели, сумме и сроку. Подходящие продукты показаны первыми, причины результата отображаются на карточках. Во время изменения параметров прежние рекомендации скрываются; доступны загрузка, ошибка, повтор и сообщение об отсутствии предложений.
- Расчёт платежа отправляется после паузы в изменении параметров. Старый платёж не выдаётся за результат нового расчёта; при ошибке есть повтор. Высота результата сохраняется при пересчёте и ошибке, поэтому калькулятор не сжимается; при смене ширины экрана высота измеряется заново. Общая сумма выплат и проценты — приблизительные диапазоны, полученные из округлённых сервером платежей, а не отдельный клиентский расчёт ставки. Они не включают комиссии и не заменяют договор или ПСК.
- У овердрафта сервер задаёт срок 12 месяцев. Клиент показывает фиксированный срок действия лимита без ползунка «12–12» и использует серверный предварительный расчёт с пояснением о зависимости фактических платежей от использования лимита.
- При выборе продукта сумма и срок ограничиваются его рамками. Изменения явно описываются перед оформлением. Окно условий использует текущие параметры калькулятора, повторно сверяя их с деталями продукта.
- Кнопка «Что понадобится» открывает небольшое модальное окно поверх страницы со списком действий из API; содержимое карточки не раздвигается. Требования загружаются при открытии, предусмотрены загрузка, ошибка с повтором и пустой ответ. В окне условий показаны описание, требования и предварительный расчёт; размер окна — до 1120 px. Описательная метка карточки берётся из справочника целей, без выдуманных рекламных условий. Срок и годовая ставка на карточках показаны шрифтом 15 px.
- «Оформить» создаёт черновик через `POST /applications`, передаёт продукт, показанные сумму и срок, выбранную цель при её наличии и открывает маршрут из ответа сервера. Отсрочка описана в условиях продукта; её выбор остаётся в мастере заявки и не подставляется в расчёт каталога автоматически.

Отличия от HTML-макета: вместо демонстрационного выбора ставки используются диапазон ставок API и выбор продукта. Результаты сервера имеют приоритет над примерами сумм, ставок и требований из макета.

По указанию пользователя браузер, тесты и автоматические проверки при этой доработке не запускались. Сквозное создание заявки и визуальное соответствие требуют ручной проверки пользователя на его окружении с сервером.

## Открытие результата общего поиска

Подключено к [общему поиску клиента](search.md). Результат открывается по URL, окно закрывается с удалением параметра. Чтение конкретного объекта проверяет доступ на сервере и не зависит от ограничений списка. Ошибка открытия показывается явно.
Продукт: `/products?product=CODE`, условия читаются существующим `GET /api/v1/products/{code}`. Переход сам по себе не создаёт заявку.
