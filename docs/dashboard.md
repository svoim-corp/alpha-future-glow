# Dashboard — настройка главной

Зона Dashboard (`backend/internal/dashboard`, разработчик B): сохранённая раскладка виджетов главной клиента. Схема БД —
`dashboard`.

Зона хранит только документ настройки: типы виджетов, координаты, размеры, ID источников и фильтры. Сумм, историй и
пользовательских текстов в нём нет, содержимое виджетов зона не загружает — его клиент берёт из API бизнес-зон.

Сервер реализован, клиент подключён через RTK Query: чтение и сохранение с проверкой версии, идемпотентный повтор и явный перенос прежней настройки устройства при отсутствии серверной записи. Поведение редактора и границы проверки — [home-dashboard.md](home-dashboard.md).

## Область и доступ

- Одна запись на пару `(userId, companyId)` из серверной сессии. Ни пользователь, ни компания из тела запроса не
  принимаются. Настройка одного сотрудника компании не меняет главную другого.
- Доступно пользователю с ролью `CLIENT` и компанией. Без сессии — `401 UNAUTHORIZED`, сотрудник банка или пользователь
  без компании — `403 FORBIDDEN`. Чужие настройки не возвращаются ни при каких параметрах.
- Ответы `GET` и `PUT` — с `Cache-Control: private, no-cache`; успешный документ — с `ETag: "<revision>"`.
- `POST /admin/seed/reset` удаляет все настройки и ключи идемпотентности.

## Документ

```json
{
  "revision": "8efc6500-8373-4e9d-9f0a-a5d9efae1175",
  "updatedAt": "2026-10-22T10:00:00Z",
  "config": {
    "schemaVersion": 1,
    "widgets": [
      { "id": "77a45b12-67cf-4e29-848a-0db98fb07eb8", "type": "loan", "x": 0, "y": 0, "w": 4, "h": 3, "settings": { "loanId": "l-55" } }
    ]
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `revision` | string | Непрозрачный токен версии записи (сейчас UUID v4). Меняется при каждом сохранении. Не путать со `schemaVersion` |
| `updatedAt` | string | Время сохранения, ISO 8601 UTC, формирует сервер |
| `config` | object | Настройка — ровно то, что клиент отправил в `PUT` |
| `config.schemaVersion` | int | Версия формата, сейчас только `1` |
| `config.widgets` | array | От 0 до 30 виджетов; пустой массив — сохранённая пустая главная, а не отсутствие настройки |

## API

### `GET /me/dashboard`

Реализовано. Сохранённая настройка текущего пользователя в его компании.

| Ответ | Когда |
|---|---|
| `200` | Документ, заголовок `ETag: "<revision>"` |
| `204` | Настройку ещё не сохраняли — клиент строит исходную раскладку |
| `401` / `403` | Нет сессии / не клиент или нет компании |

### `PUT /me/dashboard`

Реализовано. Заменяет настройку целиком и атомарно. Отдельных команд добавления, перемещения и удаления виджета нет:
удаление карточки — обычный `PUT` нового массива.

Тело — `config` целиком, без оболочки, `revision`, `updatedAt`, `userId` и `companyId`:

```json
{
  "schemaVersion": 1,
  "widgets": [
    { "id": "widget-payments", "type": "payments", "x": 0, "y": 0, "w": 8, "h": 3, "settings": { "days": 7, "loanId": null } },
    { "id": "widget-drafts", "type": "drafts", "x": 8, "y": 0, "w": 4, "h": 3, "settings": {} }
  ]
}
```

Заголовки:

| Заголовок | Обязателен | Значение |
|---|---|---|
| `If-Match` | один из двух | `"<revision>"` — изменение существующей записи; кавычки необязательны |
| `If-None-Match` | один из двух | `*` — первое сохранение; запись, появившаяся после чтения, не перезаписывается |
| `Idempotency-Key` | нет, рекомендуется | Ключ одной логической попытки, до 128 символов. Повтор неизменённой команды — с тем же ключом, изменённый документ — с новым |

Ответ `200` — новый документ, как у `GET`, с новым `revision` и `ETag`. Первое сохранение тоже отвечает `200`.

Ошибки (формат `{code, message, fields?, traceId}`):

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Некорректный JSON, тело больше 64 КиБ, нарушен формат v1, недоступная новая привязка; указаны оба заголовка версии; `If-None-Match` не `*`; `Idempotency-Key` длиннее 128 |
| 400 | `DASHBOARD_SCHEMA_UNSUPPORTED` | `schemaVersion` не `1`; остальное тело не проверяется. Клиент не пересохраняет частично прочитанный документ |
| 401 / 403 | `UNAUTHORIZED` / `FORBIDDEN` | Нет сессии / не клиент или нет компании |
| 409 | `IDEMPOTENCY_KEY_REUSED` | Тот же `Idempotency-Key` уже использован с другим телом |
| 412 | `DASHBOARD_VERSION_CONFLICT` | `If-Match` не совпал с текущей ревизией или записи нет; при `If-None-Match: *` запись уже есть. Черновик клиента остаётся, пользователь может перечитать сохранённую версию |
| 428 | `PRECONDITION_REQUIRED` | Нет ни `If-Match`, ни `If-None-Match` |
| 5xx | `INTERNAL` | Временная ошибка; клиент не закрывает редактор и разрешает повтор |

Порядок проверок: сессия и роль → заголовки версии и ключа → разбор и формат тела → повтор по ключу → версия →
привязки → запись. Проверка версии и запись выполняются в одной транзакции условным `INSERT`/`UPDATE`.

**Идемпотентность.** Сервер хранит SHA-256 сырого тела и результат успешного сохранения; ключи изолированы по
пользователю и компании. Повтор с тем же ключом и телом возвращает исходный документ (тот же `revision` и `ETag`), даже
если запись уже создана или после неё настройку сохраняли снова. Параллельные повторы одной команды получают один
результат. Без ключа повтор после потерянного ответа получит `412`.

Пример ошибки формата:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Настройка главной не прошла проверку",
  "fields": [
    { "field": "widgets[1].x", "code": "INVALID", "message": "Виджет пересекается с виджетом 1" },
    { "field": "widgets[2].settings.days", "code": "INVALID", "message": "Недопустимое значение" }
  ],
  "traceId": "79177a50"
}
```

## Формат v1

### Виджет

| Поле | Правило |
|---|---|
| `id` | Строка 1–64 символа, уникальна в документе |
| `type` | Один из 16 типов ниже |
| `x` | Целое 0–11, `x + w <= 12` |
| `y` | Целое 0–200 |
| `w`, `h` | Пара из допустимых размеров типа |
| `settings` | Объект: все ключи своего типа обязательны, других ключей нет; `{}` — у типов без настроек |

Все поля обязательны. Неизвестные поля документа и виджета, неизвестные типы и ключи `settings` — ошибка, а не тишина:
старый клиент не должен молча терять виджеты нового формата. Прямоугольники не пересекаются (касание краями допустимо).
Координаты описывают компьютерную сетку из 12 колонок; мобильная раскладка не сохраняется.

Пути полей в ошибках: `widgets[i].id` (длина, повтор), `widgets[i].type`, `widgets[i].x` (выход за сетку, пересечение —
на более позднем виджете), `widgets[i].w` (недопустимый размер), `widgets[i].settings.<ключ>`. Коды — `REQUIRED`, `INVALID`.

### Типы

| `type` | Допустимые `[w,h]` | `settings` |
|---|---|---|
| `applications` | `[8,3]`, `[8,4]`, `[12,3]` | `filter`: `all` / `attention` |
| `loan` | `[4,3]`, `[4,4]`, `[6,3]` | `loanId`: ID кредита или `null` — не выбран |
| `payment` | `[4,2]`, `[4,3]`, `[6,2]` | `loanId`: ID кредита или `null` — все действующие |
| `debt` | `[4,2]`, `[4,3]` | `{}` |
| `quick` | `[4,2]`, `[4,3]`, `[8,2]` | `actions`: 1–5 разных кодов из `apply`, `plan`, `credits`, `calendar`, `support`; порядок значим |
| `calendar` | `[6,4]`, `[8,4]`, `[12,4]` | `source`: `all` / `payments` / `plans` |
| `plans` | `[6,4]`, `[6,5]`, `[12,4]` | `filter`: `upcoming` / `ideas` |
| `application` | `[4,3]`, `[6,3]`, `[8,3]` | `applicationId`: ID заявки или `null` — не выбрана |
| `loans` | `[8,3]`, `[8,4]`, `[12,3]` | `status`: `ACTIVE` / `CLOSED` |
| `payments` | `[8,3]`, `[4,3]`, `[8,4]` | `days`: `7` / `30`; `loanId`: ID кредита или `null` |
| `offers` | `[6,4]`, `[4,4]`, `[8,4]` | `filter`: `current` / `all` |
| `drafts` | `[4,3]`, `[6,3]`, `[8,3]` | `{}` |
| `planFunding` | `[6,4]`, `[4,4]`, `[8,4]` | `planId`: ID плана или `null` — не выбран |
| `notifications` | `[4,4]`, `[6,4]`, `[8,4]` | `filter`: `unread` / `all` |
| `tickets` | `[6,3]`, `[4,3]`, `[6,4]` | `filter`: `active` / `answered` / `all` |
| `funding` | `[4,3]`, `[6,3]`, `[8,3]` | `{}` |

Пользовательские URL, HTML, имена компонентов и стили не принимаются. Новый тип добавляется в эту таблицу и в
`backend/internal/dashboard/config.go`; `schemaVersion` при расширении набора вариантов не меняется, старые документы не
мигрируют.

Семантика фильтров — для клиента, сервер хранения по ней ничего не загружает: `offers.current` — неистёкшие непринятые
предложения и принятые в `SIGNING`, `all` — ещё и истёкшие; `payments.days` — дни от текущего дня UTC включительно;
`tickets.active` — `OPEN` и `ANSWERED`.

### Привязки к объектам

`loanId`, `applicationId`, `planId` — `null` или строка до 128 символов из латинских букв, цифр, `_` и `-`; пустая
строка недопустима.

- **Новая привязка** — ID того же вида, которого нет в текущей сохранённой настройке. Сервер проверяет, что объект
  принадлежит компании пользователя: кредит — через Servicing (закрытый допустим), заявка — через Origination, план —
  через Planner (в любом состоянии). Отсутствующий и чужой объект дают одинаковую ошибку `400 VALIDATION_ERROR` по полю
  привязки: «Источник не найден или недоступен».
- **Уже сохранённая привязка** не перепроверяется: потерянный доступ к старому договору или удалённая заявка не
  блокируют остальные изменения. Сервер не подменяет её другим объектом; виджет показывает ошибку доменного `GET` (404).

## Для других зон

Зона ничего не отдаёт другим зонам и использует:

| Интерфейс | Поставщик | Зачем |
|---|---|---|
| `shared.Applications.Application` | Origination | компания заявки |
| `shared.LoanOwners.LoanCompany` | Servicing | компания кредита |
| `shared.PlanOwners.PlanCompany` | Planner | компания плана |
