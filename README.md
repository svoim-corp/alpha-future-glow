# Умный кредитный кабинет

Проект команды **«Glow»** для **«Альфа-Будущее Хакатон»**, первый онлайн-тур.

Веб-кабинет для юрлиц и ИП, которые уже обслуживаются в банке. В нём можно подобрать
кредитный продукт, подать заявку, получить решение банка, подписать договор и дальше
обслуживать кредит. Сотрудник банка работает в отдельном рабочем месте: очередь заявок,
результаты проверок и скоринга, ручное решение. Внешние источники (ЕГРЮЛ, БКИ, ФНС и др.)
и выдача кредита смоделированы моками. К реальным банковским системам проект не подключается.

## Возможности

**Клиент (`CLIENT`)**
- Настраиваемая главная с виджетами и общий поиск по кабинету.
- Каталог продуктов: подбор по цели, калькулятор платежа, создание черновика заявки.
- Двухэтапная заявка. Первый этап даёт предварительное решение и лимит, второй — полную анкету
  и согласия. Реквизиты, полномочия и обороты компании подставляются из данных банка.
- Трекер заявки: статусы, ответы на запросы банка, принятие оффера, подписание и выдача.
- Кредиты: график платежей, платёжный календарь, задолженность, история операций,
  выгрузка графика в CSV и PDF.
- Финансовый планер: планы потребностей и рекомендации кредитных продуктов.
- Поддержка: FAQ, обращения и **ИИ-ассистент**. Ассистент работает на локальной LLM через
  Ollama и RAG по базе знаний. Он отвечает на вопросы, подбирает и рассчитывает кредит,
  сообщает статус заявки и ближайшие платежи. Черновик заявки или обращение он создаёт
  только после подтверждения пользователя.

**Сотрудник банка (`BANK_OFFICER`)**
- Очередь заявок со сводкой по статусам, фильтрами и назначением исполнителя.
- Разбор заявки: анкета, полнота данных, результаты внешних проверок и скоринга.
- Запрос информации у клиента и ручное решение: одобрение, отказ или встречные условия.

## Стек

| Часть | Технологии |
|---|---|
| `backend/` | Go 1.25, Gin, PostgreSQL 17 (sqlx + pgx, миграции goose), модульный монолит: пакет и схема БД на доменную зону |
| `frontend/` | React 19, TypeScript, Redux Toolkit / RTK Query, React Router, Vite, Feature-Sliced Design |
| ИИ-ассистент | Ollama: Qwen3-8B (ответы), BGE-M3 (эмбеддинги); pgvector и полнотекстовый поиск PostgreSQL |
| `deploy/` | Docker Compose: БД, моки внешних сервисов, сервер, клиент за nginx и опциональный ИИ-профиль |

## Структура репозитория

```
backend/    REST API /api/v1 (cmd/api), моки внешних сервисов (cmd/mocks),
            индексатор базы знаний ассистента (cmd/support-index)
frontend/   кабинет клиента и рабочее место банка (/bank/*)
deploy/     docker-compose для запуска всего проекта
docs/       описания модулей и контрактов API
```

## Быстрый старт

Нужны Docker и Docker Compose 2.24 или новее. Из корня репозитория:

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

| Что | Адрес |
|---|---|
| Кабинет | http://localhost:3000 |
| API | http://localhost:3000/api/v1 (через nginx) или http://localhost:8080/api/v1 |
| Swagger UI | http://localhost:8080/api/docs |

Порты, учётные данные БД и профиль сервера можно переопределить в `deploy/.env`
(образец — `deploy/.env.example`). Профиль `demo` (по умолчанию) включает сброс демо-данных
через `POST http://localhost:8080/admin/seed/reset`.

### Запуск с ИИ-ассистентом

Ассистент включается профилем `ai`. При первом запуске скачиваются веса моделей
(примерно 6,5 ГБ), затем строится индекс базы знаний. После этого всё работает без интернета.

```bash
# на CPU
docker compose -f deploy/docker-compose.yml --profile ai up -d --build

# с NVIDIA GPU
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.ai-gpu.yml --profile ai up -d --build
```

Дождитесь окончания `ai-index` (`docker compose -f deploy/docker-compose.yml logs -f ai-models ai-index`)
и откройте http://localhost:3000/support. Без профиля `ai` остальной кабинет, FAQ и обращения
работают как обычно. Требования к железу, офлайн-режим, пересборка индекса и сценарий проверки
описаны в [`deploy/SUPPORT_AI.md`](deploy/SUPPORT_AI.md).

## Локальная разработка

**Сервер** ([подробнее](backend/README.md)):

```bash
docker compose -f deploy/docker-compose.yml up -d db
cd backend
export DATABASE_URL='postgres://cabinet:cabinet@localhost:5432/cabinet?sslmode=disable'
HTTP_ADDR=:8090 go run ./cmd/mocks &   # моки внешних сервисов
make run                               # API на :8080
make fmt vet build test                # проверки
```

**Клиент** ([подробнее](frontend/README.md), нужен Node.js 22):

```bash
cd frontend
cp .env.example .env
npm ci
npm run dev        # http://localhost:3000, /api проксируется на :8080
npm run dev:mock   # без сервера: API обслуживает MSW в браузере
npm run check      # typecheck, ESLint, Steiger (FSD), тесты
```
