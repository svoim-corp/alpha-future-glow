# Локальный ассистент поддержки

## Запуск

Требуются Docker Desktop с Linux containers / WSL2 и Docker Compose ≥ 2.24.
Для GPU — драйвер NVIDIA с поддержкой WSL2. Проверенная целевая конфигурация:
RTX 3060 12 ГБ; рекомендуем 16 ГБ RAM и 20 ГБ свободного места.
CPU-запуск возможен, но существенно медленнее. Параллельно обрабатывается один ответ.

Из корня проекта, с NVIDIA GPU:

```powershell
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.ai-gpu.yml --profile ai up -d --build
docker compose -f deploy/docker-compose.yml logs -f ai-models ai-index
```

Для CPU уберите `-f deploy/docker-compose.ai-gpu.yml`. Интерфейс: http://localhost:3000/support.
Демо-вход: `smirnov` / `demo123`. Веса впервые скачиваются автоматически:
Qwen3-8B Q4_K_M (~5.2 GB) и BGE-M3 (~1.2 GB); дождитесь завершения `ai-index`.
Имена моделей в `.env.models` должны совпадать с `OLLAMA_MODEL` и
`OLLAMA_EMBEDDING_MODEL`, если вы переопределяете их в окружении.

Без ИИ: `docker compose -f deploy/docker-compose.yml up -d --build`.
Обычные страницы, FAQ и обращения продолжают работать. Ошибка модели не должна
превращаться в выдуманный ответ. Браузерный `npm run dev:mock` не имитирует LLM:
он объясняет необходимость запуска серверной части.

Во время разработки можно использовать установленный Ollama вместо контейнера:
`OLLAMA_BASE_URL=http://host.docker.internal:11434` для сервера в Docker,
или `http://localhost:11434` для Go на хосте. Модели загружаются в этот Ollama отдельно.

## База знаний и воспроизводимость

Материалы: `backend/internal/support/knowledge/*.md` и текущие FAQ сервера.
Пользовательские диалоги и данные компаний в индекс не входят. BGE-M3 используется
только для dense embeddings размерности 1024; sparse-возможности модели не используются.
Поиск сочетает pgvector и русскоязычный полнотекстовый индекс, RRF, top-5.
Для небольшого корпуса используется точный поиск, без ANN-индекса.

После правки корпуса пересоберите `ai-index`, затем:

```powershell
docker compose -f deploy/docker-compose.yml --profile ai run --rm --build ai-index
```

На хосте: `cd backend`, задайте `DATABASE_URL`, `OLLAMA_BASE_URL` и выполните
`go run ./cmd/support-index`. Сначала должны быть применены миграции API.
Замена корпуса атомарная: ошибка embedding не удаляет действующий индекс.

Модели хранятся в постоянном томе `ollama-data`. Для фиксации точных артефактов:

```powershell
docker compose -f deploy/docker-compose.yml exec -T ollama ollama show qwen3:8b-q4_K_M
docker compose -f deploy/docker-compose.yml exec -T ollama cat /root/.ollama/models/manifests/registry.ollama.ai/library/qwen3/8b-q4_K_M
docker compose -f deploy/docker-compose.yml exec -T ollama cat /root/.ollama/models/manifests/registry.ollama.ai/library/bge-m3/567m
```

Сохраняйте manifest JSON с SHA256 слоёв вместе с демонстрационной версией.
Веса не включаются в Git. Для полностью автономного переноса заранее экспортируйте
образы через `docker save`, сохраните том моделей и том БД с готовым индексом.
После подготовки запускайте `db mocks backend frontend ollama`, не перезапуская
шаг скачивания `ai-models`. Никаких платных или облачных API в рантайме нет.

## Существующие данные PostgreSQL

Образ БД остаётся PostgreSQL 17 / Alpine; pgvector 0.8.1 собирается отдельно.
Миграции чата не требуют расширения: его устанавливает команда индексации.
Не выполняйте `down -v`, не удаляйте старый том.

Перед заменой образа существующей базы сохраните `pg_dump`, сделайте копию тома
при остановленной БД и проверьте запуск копии на новом образе. Сверьте число заявок,
кредитов и обращений, примените миграции, проверьте обычный сценарий и только потом
используйте основной том. При переходе между Alpine и Debian используйте логический
dump/restore, а не подключение старого тома. Новая установка не требует переноса.

## Проверка сценария

1. Войти клиентом и открыть «Поддержка → Ассистент».
2. Спросить об отличиях овердрафта; раскрыть справочные материалы.
3. Подобрать кредит на оборудование за 2 млн рублей на 24 месяца.
4. Рассчитать платёж по выбранному продукту; сравнить со штатным калькулятором.
5. Попросить создать черновик. До нажатия «Подтвердить» заявки быть не должно.
6. Подтвердить, открыть «Мои заявки», проверить сохранённые параметры.
7. Повторить подтверждение / обновить страницу: второй заявки не появляется.
8. Спросить о статусе заявки и ближайших платежах. Пустой список — корректный результат.
9. Подготовить и подтвердить обращение, проверить «Мои обращения».
10. Выключить Ollama: обычный кредитный сценарий, FAQ и обращения работают.
11. После скачивания отключить доступ в интернет и повторить пункты 2–9.

Для замера производительности фиксируйте время ответа, поиск, `eval_count` /
`eval_duration` Ollama и `nvidia-smi`. Холодную загрузку учитывайте отдельно.
Не делайте выводы о скорости по размеру файлов весов: требуется запас под KV-cache.

## Ограничения

Одна реплика API владеет последовательным worker. При её запуске незавершённые ответы
помечаются FAILED; действия автоматически не повторяются. Подтверждение идемпотентно
по сохранённому actionId даже при сбое после создания объекта. Диалоги — последние
100, сообщения — последние 100. Старые сообщения остаются в БД, в контекст попадает
ограниченная недавняя история. Операторская обработка обращений не реализована.
